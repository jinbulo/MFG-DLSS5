# FS4 MFG — 2026-10-05

Real multi-frame generation (DLSS-G) + DLSS 5 neural rendering for **Fallout 4**, on top of
an existing ENB setup, without touching it.

**Package:** `FS4-MFG-2026-10-05.zip` (159.6 MB, 80 files)
**SHA-256:** `45EA045806B1648B6538B3A37C61337E2DB259FB8DBF7566FC78D11CFF9EAB29`
**Nexus page:** https://www.nexusmods.com/fallout4/mods/109634

## Verified builds

| Game | Script extender | ENB |
| --- | --- | --- |
| Fallout 4 **1.10.163** | F4SE **0.6.23** | ENB **0.496** |
| Fallout 4 **1.11.240** | F4SE **0.7.9** | ENB **0.501** |

Both were verified in-game: swapchain takeover, 4x frame generation, 100% non-zero motion
vectors, `ui_exact` UI compositing, no crashes. Other builds are untested — install the ENB
and F4SE that match your build and try it. ENB is **mandatory** (it is what makes the engine
publish motion vectors) and is **not** bundled — get it from https://enbdev.com/.

## Install

1. Install the game, the matching F4SE, and the matching ENB. Set `EnableFPSLimit=false` in
   `enblocal.ini`.
2. Extract this archive **outside** the game folder and run `install.bat`. It finds the game,
   backs up every file it overwrites into `MFG-backup-<timestamp>\`, and copies the mod in.
   (MO2 users: copy the archive contents into `overwrite\Root` and put
   `Data\F4SE\Plugins\fs4mvcam.dll` in place by hand.)
3. Set the game to **borderless windowed**, turn **NVIDIA Smooth Motion** off, and launch
   through `f4se_loader.exe` (or the bundled `launch-f4se.bat`). Launching from Steam works
   too — just make sure Steam runs the F4SE loader, and on 1.10.163 set the update policy to
   "Only update this game when I launch it" so Steam cannot bump you to 1.11.x.

## Highlights in this build

- **`ui_exact` is on by default** — the HUD, subtitles and dynamic bars are lifted out before
  the DLAA pass and composited back exactly, so the UI keeps its original pixels.
- **Removed `hudless_tag=2/3`** (measured twice on 2026-10-02, worse both times; the code is
  gone and the value is clamped to 0/1).
- **Fallout 4-specific HUD-less capture fix** — FO4 binds the back buffer without depth
  several times per frame; only the first binding is the pre-HUD scene, and that is what the
  capture point now takes.
- **Installer / disable / restore scripts** (bilingual, auto game detection, version gate,
  automatic elevation, backup before overwrite).
- `dlss5-lab-overlay.addon64` added to the one-click disable list; hotkeys unified
  (F5/F6 RenoDX, F7 overlay, F8 effects, F10 screenshot); new `launch-f4se.bat`.
- **No bundled ENB** — your own ENB is never touched.

## Known issues

- Keep `GEOM_ENABLE` on. With the geometry mask off, the guide chain trusts motion vectors
  that are not valid there and subtitles visibly blur.
- The HUD is still interpolated inside *generated* frames — that is DLSS-G's own HUD handling;
  `ui_exact` fixes the DLAA blur, not the interpolation.
- Occasional multi-millisecond hitches on the copy, and rare multi-hundred-millisecond frames
  inside the DLSS feed — under investigation.
- On 1.11.240, `fs4mvcam.dll` is refused by F4SE 0.7.9 (`no version data` in `f4se.log`).
  This is known and harmless: motion vectors there come from ENB + the engine buffer,
  verified 100% non-zero.
